# 中医大脑 V2 项目方案设计与阶段路线

**日期：** 2026-11-12

**状态：** 待确认

**选定架构：** 方案 A，证据底座 + 模块纵向切片

## 一、项目意图

中医大脑 V2 以倪海厦人纪教学体系为主要研究线索，以原始医书为证据基础，建设一个集针灸、本草、内经、经方、辨证论治和 AI 辅助学习于一体的中医知识系统。系统首先解决知识组织和证据链问题，再逐步提供检索、解释、对比和 AI 辅助学习。

辨证不能全部推迟到最终阶段。针灸、本草、内经和经方在各自阶段都要建立本领域的辨证条件、应用边界、鉴别关系和来源证据；第五阶段再做跨领域统一，而不是第一次开始整理辨证。

开发顺序确定为：

1. 证据底座与治理机制
2. 针灸模块
3. 神农本草经模块升级
4. 黄帝内经模块
5. 综合辨证与 AI

其中第五阶段拆成两个里程碑：

- 5A：统一跨书辨证知识关系
- 5B：接入 AI 检索和辅助学习

现有方剂、本草和六经数据全部保留。后续工作采用增量迁移和兼容读取，不覆盖已经审核的内容。

## 二、调查结论

当前仓库已经具备以下基础：

- 方剂目录共 299 条：《伤寒论》113 条，《金匮要略》186 条。
- 已正式验收方剂 114 条，其余 185 条明确标为待校。
- 神农本草经已有 351 味结构化条目。
- 六经辨证已有 6 个一级条目，太阳病已有初步内容。
- 现有测试 140 项通过，1 项金匮批次测试按计划跳过。
- 当前页面和 API 以方剂、中药、六经为主，针灸尚未接入。

本地《倪海厦人纪系列之针灸教程》共 216 页，目录包含六章和穴位拼音索引、穴位笔画索引、治症索引。该资料的校勘序明确说明，它是基于网络流传讲稿扫描件、由民间整理者校勘的转录版本，并非原始出版原书。系统中的来源类型必须准确记录为“校勘转录版”，不能标注为“原书”。

该 PDF 的抽样文本层存在严重乱码，不能依赖普通 PDF 文本抽取。针灸模块必须使用页图作为稳定证据，文本通过 OCR 或人工录入获得，并保留 OCR 原稿、校字稿和最终发布稿三个层次。

## 三、目标与非目标

### 目标

- 每条正式知识都能定位到具体书籍、版次、章节、PDF 页码和原文片段。
- 原文、作者或讲授者观点、整理者说明、系统推导内容严格分层。
- 自动生成、待核实、已审核内容在数据层和页面上都可区分。
- 经络、穴位、本草、内经理论、方剂和证候之间建立有出处的关联。
- 后续 AI 只能使用可追溯知识，并能展示引用和不确定性。
- 每个阶段都具有独立可验收的成果，不需要等待全部模块完成。

### 非目标

- 当前阶段不重写已经通过测试的方剂业务。
- 当前阶段不构建覆盖全部中医学科的最终本体。
- 当前阶段不生成面向普通用户的个性化诊断、处方或针刺操作指令。
- 当前阶段不把 Book to Skill 生成的摘要当作正式原文。
- 当前阶段不进行 AI 模型训练，也不建设依赖模型记忆的问答。

### 失败条件

即使页面可以运行，只要出现以下任一情况，该阶段仍视为失败：

- 内容无法回到来源页或原文片段。
- 自动抽取结果被显示为人工审核结果。
- 不同版本被静默合并成一个结论。
- 高风险内容被包装成普通人可以直接执行的步骤。
- 现有已审核方剂或本草数据被覆盖。

## 四、方案选择

### 方案 A：证据底座 + 模块纵向切片

先建立共享的来源、证据、状态和审校机制，再按模块逐个完成数据、API、页面和验收。每个模块都可以独立交付，后续模块复用同一证据底座。

优点：

- 针灸模块可以最快形成完整闭环。
- 现有方剂和本草数据不必立即重构。
- 来源逻辑只实现一次，减少各模块口径分裂。
- 后续扩展黄帝内经和 AI 时不需要推翻已有结构。

代价：

- 针灸开始前需要先完成一轮证据模型设计。
- 不同模块的数据字段仍有各自领域结构，不能完全共用一个表。

### 方案 B：复制现有方剂模式

每个模块复制一套来源、校对和页面逻辑。初期实现最快，但会形成多套状态口径，后期跨模块关联和 AI 引用成本明显增加。

### 方案 C：先建统一知识图谱

先设计完整中医本体和关系图，再开发各模块。理论覆盖最完整，但会把可见成果推迟很久，并在术语和原文尚未清点时产生过度建模。

本方案采用 A。证据底座只覆盖所有模块都需要的公共部分，领域数据仍按针灸、本草、内经、方剂和辨证分别组织。

## 五、总体信息架构

### 5.1 来源层

来源层负责记录资料本身，不解释医学内容。

每条来源至少包含：

- `source_id`
- 书名、篇章或讲义名称
- 作者、讲授者、整理者、校勘者
- 版本名称和版本日期
- 来源类型：原典、讲义转录、校勘转录、视频同步稿、结构化快照
- 文件格式和 SHA-256
- PDF 总页数
- PDF 页码与印刷页码的对应关系
- 文件在仓库中的相对路径
- 已知 OCR 问题或缺失页

原始 PDF 只读取，不在处理流程中修改。

### 5.2 页与片段层

每条证据由页级快照和文本片段组成：

- `page_id`
- `source_id`
- `pdf_page`
- `printed_page`
- 页图路径和页图哈希
- OCR 原稿
- 校字稿
- OCR 状态
- 章节路径
- 段落或行范围

页图是稳定定位依据。OCR 文本和校字文本是检索依据。两者不能互相覆盖。

### 5.3 知识记录层

不同模块使用不同领域字段，但共享以下公共字段：

- `id`
- `record_type`
- `canonical_name`
- `aliases`
- `summary`
- `source_span_ids`
- `generation_status`
- `evidence_status`
- `review_status`
- `risk_level`
- `created_at`
- `updated_at`
- `version`

`record_type` 首批包括：

- `theory`
- `meridian`
- `acupoint`
- `point_selection_rule`
- `technique`
- `condition_teaching`
- `herb`
- `classic_chapter`
- `formula`
- `syndrome`
- `relation`

### 5.4 关系层

关系必须单独记录，不直接写入某一方的内容字段。首批关系类型：

- 经络—穴位
- 穴位—主治或症状
- 穴位—配穴
- 证候—穴位
- 本草—方剂
- 方剂—药味
- 方剂—证候
- 方剂—方剂：同名、类方、加减、跨书
- 内经篇章—理论概念
- 理论概念—针灸、本草、方剂

每条关系包含来源证据和关系状态。由系统推导出的关联只能标为候选关系。

## 六、状态模型与内容分层

不使用一个状态字段混合所有含义，改用四个正交状态。

### 生成状态

- `auto`：机器自动抽取
- `assisted`：机器辅助、人工修订
- `manual`：人工录入

### 证据状态

- `unlinked`：尚未关联来源
- `anchored`：已关联页码或连续片段
- `verified`：原文和定位已经人工核对
- `conflicted`：来源之间存在冲突

### 审校状态

- `pending`：待审
- `needs_changes`：需修改
- `approved`：已审核
- `rejected`：不予采用

### 风险状态

- `standard`：一般学习内容
- `high_risk`：剂量、毒性、针刺深度、放血、火针等
- `emergency`：急症、危症或必须就医的内容

页面必须分别展示这四个维度。一个条目可以是“人工录入、原文已核对、仍待审核”，不能只用“已完成”概括。

内容同时分为五种角色：

1. 原典或转录原文
2. 倪海厦讲解
3. 其他注解
4. 校勘或版本差异
5. 整理者理解或系统推导

不同角色的文字不得拼接成一段后失去归属。

## 七、Book to Skill 的定位

截至 2026-11-12，Book to Skill 的公开说明已经列出 Codex，并说明默认把生成的跨 Agent Skill 放在 `~/.agents/skills/<slug>/`。项目若需要把技能纳入版本控制，可以保留项目内 `.agents/skills/`，但必须先做一次 Codex 技能发现烟雾测试；如果当前 Codex 版本不读取项目内目录，则以 `~/.agents/skills/` 作为安装目标，并在仓库中保存生成源和锁文件。参考：<https://github.com/virgiliojr94/book-to-skill>。

Book to Skill 用于把书籍拆成 Codex 可以按章节调用的技能，适合保存：

- 章节导航
- 核心术语与主题索引
- 抽取检查表
- 校对问题库
- 章节之间的关系说明
- Codex 处理该书时应遵循的工作流程

正式知识库仍需保存：

- 来源文件哈希
- PDF 页码和印刷页码
- 页图
- OCR 原稿和校字稿
- 原文证据片段
- 审校记录
- 领域实体及其关系

因此，Book to Skill 产物是加工和检索辅助，不是原文证据库。每个生成技能应配套一个 `SOURCE.lock.json`，记录它依据的原始文件、哈希、章节范围和生成日期。

针灸 PDF 当前文本层存在乱码，因此不能把原始 PDF 直接交给 Book to Skill 后接受其自动抽取结果。正确顺序是：

1. 页图识别和必要的人工校字
2. 生成按章节整理的清洁 Markdown 或文本
3. 对清洁文本运行 Book to Skill
4. 将 Skill 结果与原始页图、章节页码和正式知识记录交叉核对

医学资料包含表格、索引、术语和操作步骤，默认优先使用结构化抽取模式；纯叙述性内容可以使用文本模式。单本书内容过大时，按上下册、卷次或大章节拆成多个 Skill，不必强行生成一个超大技能。

建议的项目内生成位置为：

```text
.agents/skills/<book-skill-name>/
  SKILL.md
  chapters/
  glossary.md
  patterns.md
  cheatsheet.md
  SOURCE.lock.json
```

目录名不直接代表正式知识状态。技能文件中的候选结论在进入正式数据前仍需经过来源映射和审校。

已验证的官方使用者路径是 `~/.agents/skills/<book-skill-name>/`。项目内 `.agents/skills/` 是否被当前 Codex 自动发现，应在阶段 0 用一个最小测试 Skill 验证后再锁定。不能因为目录名正确就假定已经加载。

## 八、分阶段路线

### 阶段 0：证据底座与项目治理

目标是建立所有模块共同遵守的来源和审校规则。

建设内容：

- 编写项目级 `AGENTS.md`，固定资料处理规则、状态词表和安全边界。
- 建立持久化交接记录，记录当前阶段、已完成批次、未决问题和下一任务。
- 建立来源目录和版本目录。
- 建立统一证据 schema。
- 建立审校事件记录。
- 为现有方剂、本草、六经数据增加只读兼容说明。
- 建立来源完整性测试和禁止伪造引用测试。
- 用一个最小 Book to Skill 测试项目内和用户级技能目录在 Codex 中的实际发现行为。

完成条件：

- 新模块能通过统一的 `source_id` 找到来源文件。
- 任意正式知识都能解析到有效来源片段。
- 自动生成、待核实、已审核状态可以分别测试。
- Book to Skill 的实际加载位置已经通过烟雾测试确认。
- 现有 140 项测试保持通过。

### 阶段 1：针灸知识库

针灸是第一个完整纵向模块。

页面提供两个同时成立的浏览维度：

- 按原书学习：六章顺序、原书目录、章节正文、注解和页码
- 按临床学习主题查询：症状、传统证候、经络和穴位

两个维度读取同一份知识数据，不允许维护两套互相矛盾的穴位或治症数据。

页面一级结构：

1. 针灸基础与安全边界
2. 经络与奇经八脉
3. 穴位资料
4. 取穴、配穴与针刺技法
5. 病证与教学案例
6. 原文页、校勘与证据

#### 1.1 小范围纵向试点

先选择《手太阴肺经》范围建立一个完整经络样板，再从第六章选择一个能够覆盖多个穴位和辨证条件的治症专题作为第二个样板。两个样板共同验证：

- 经络条目
- 穴位条目
- 定位与主治
- 取穴与技法说明
- 病证教学
- 来源页图
- 关系记录
- 审校状态
- 页面展示

试点通过后再扩展到全部六章。试点用于验证字段、流程和校对工作量，不能以试点内容冒充针灸模块完成。

#### 1.2 来源清点

- 为 216 页建立页级来源记录。
- 核对 PDF 页码和印刷页码。
- 识别空白页、重复页、缺页和异常页。
- 人工或 OCR 校验六章目录。
- 以目录标题和索引建立章节分母。
- 未识别的标题必须进入 `unknown_sections`，不能静默漏掉。

#### 1.3 OCR 与校字

- 从页图生成 OCR 原稿。
- 对标题、穴位名、剂量、方向和深度字段优先人工校对。
- 保留 OCR 原稿，不直接用校字稿覆盖。
- 罕见字、缺字和无法确认的字使用显式占位状态。
- 每页记录 OCR 版本和处理批次。

#### 1.4 领域数据建设

经络记录包含：

- 名称、别名、表里关系
- 循行说明
- 相关脏腑
- 源页和证据片段
- 与该经络相关穴位

穴位记录包含：

- 规范名、别名、归经和顺序
- 原文定位
- 简化定位说明
- 传统主治
- 教材所列配穴
- 教材所列针法、灸法和放血等内容
- 风险级别
- 来源片段和版本差异

取穴与技法记录包含：

- 五输穴、原穴、络穴、郄穴、募穴、背俞穴等规则
- 子母补泻、时辰、五行等取穴逻辑
- 针刺深浅、角度、留针、补泻、灸法和禁忌
- 每条规则的原文依据和讲解归属

病证教学记录包含：

- 教材中的病证名称
- 症状或辨证线索
- 教材所列穴位和配穴
- 教材讲解
- 与其他证候的鉴别
- 风险标记和就医警示

病证内容以“教材中的学习条目”呈现，不包装为自动治疗方案。

#### 1.5 页面与 API

针灸页面需要支持：

- 按章节、经络、穴位、病证和审校状态筛选
- 穴位详情和来源抽屉
- 症状与病证检索
- 经络—穴位—病证关系浏览
- 原文、讲解、整理说明分层显示
- 自动生成与已审核状态的显式标记

针灸 API 建议首版提供：

- `GET /api/acupuncture/overview`
- `GET /api/acupuncture/chapters`
- `GET /api/acupuncture/meridians`
- `GET /api/acupuncture/points`
- `GET /api/acupuncture/points/{id}`
- `GET /api/acupuncture/techniques`
- `GET /api/acupuncture/conditions`
- `GET /api/acupuncture/sources/{page_id}`

#### 1.6 完成门槛

- 六章目录和附录索引全部完成页码映射。
- 100% 已发布穴位有来源片段。
- 100% 高风险内容具有风险状态和警示文本。
- 按原书学习和按症状、证候查询都能回到同一份穴位和来源记录。
- 所有自动抽取条目都有生成状态。
- 所有关系可以回指来源。
- 未审核条目不能显示为已审核。
- 针灸核心搜索、详情、来源查看和关系浏览通过测试。
- 原有方剂、本草和六经测试保持通过。
- “完成”以选定教材的实际覆盖和审核状态为准，不以凑满某个通用穴位数量为目标。

### 阶段 2：神农本草经模块升级

现有 351 味药是升级基线，不重新推翻。

建设内容：

- 建立该版本的实际药物分母。
- 核对 351 条与书籍目录、索引和页码的覆盖关系。
- 保留现有 `herbs.json`，新增本草证据和审校数据。
- 补强别名、药名异文、毒性、禁忌、炮制和高风险提示。
- 建立本草与方剂药味、方证和症状之间的关系。
- 区分《本经》原文、历代注释和倪海厦讲解。
- 单一药物存在多个来源时，保留版本关系和冲突状态。
- 不仅记录性味和功效，还要记录为何使用、什么条件下使用、相近药物的区别和配伍逻辑。
- 建立本草正向和反向链接：方剂可以进入药味，药味可以反查相关方剂。

完成条件：

- 可以准确回答“该版本收录多少味、已核多少味、缺多少味”。
- 不允许在没有分母时标注“神农本草经完整版”。
- 现有方剂中的药味链接不被破坏。
- 高风险药物有独立风险标记。
- 对基原、炮制、别名或古今药名对应存在争议的药物，不强行合并为一个现代药物身份。

### 阶段 3：黄帝内经模块

本地现有《黄帝内经》上册和下册视频同步文稿，共 306 页。

建设内容：

- 建立上下册来源目录和页级快照。
- 清点篇章、节标题和索引分母。
- 校正 OCR 和异常页。
- 区分经典原文、倪海厦讲解和转录整理。
- 建立《内经》原文、阴阳五行、藏象、病因病机、诊法、辨证原则、养生和经典关联子模块。
- 建立与针灸、本草、经方和辨证模块的候选关联。

经典原文和讲义稿件必须分源记录。如果现有 PDF 只提供讲义中的原文引文，不能把它自动视为独立校勘本。

完成条件：

- 两册章节覆盖率可计算。
- 所有正式理论条目具有来源片段。
- 跨模块关系具有候选或已确认状态。
- 未完成的篇章明确显示为未完成。
- 不把倪海厦解释改写成《内经》原文，也不把历史理论表述成已经过现代临床验证的事实。

### 阶段 4：经方与辨证论治整合

此阶段利用现有 299 首方剂和六经骨架，不重建目录。

建设内容：

- 保持伤寒 113 条、金匮 186 条的现有 ID 和审核结果。
- 继续完成剩余 185 条方剂校对。
- 统一六经、八纲、脏腑、气血津液和方证关系。
- 建立症状、证候、方剂、药味和针灸之间的关系。
- 增加同名方、类方、加减方、跨书同方和版本差异关系。
- 将方证对应拆分为原文主治、症状线索、病机说明和整理者理解。
- 建立“已验收方剂”和“仅目录/原文索引方剂”的使用边界。

经方加减使用独立结构记录：

| 字段 | 含义 |
|---|---|
| 原方 | 基础经方及其来源 |
| 条文条件 | 原书提出加减的前提 |
| 变化内容 | 加药、去药或剂量变化 |
| 变化方 | 关联的具体方剂 |
| 理由 | 原书或倪注给出的解释 |
| 适用边界 | 原文限制、禁忌、争议和反证 |
| 证据状态 | 已核、待核或存在冲突 |

完成条件：

- 现有方剂测试全部保留。
- 每条正式方证关系可追溯到方剂原文和辨证依据。
- 处方、剂量和加减内容带有来源及风险状态。
- 未审核方剂不进入正式 AI 知识路径。

### 阶段 5A：统一辨证知识网络

前四阶段已经分别建立针灸辨证取穴、本草应用、内经理论和经方方证。5A 不再重做内容，而是统一以下关系：

- 症状和体征与原书条文
- 传统辨证知识、支持依据、反证和不确定性
- 不同医书对同一症状或证候的相近、互补和冲突解释
- 证候与经络、穴位、针刺教学
- 证候与经方、药味、加减规则
- 所有跨领域关系的来源和审核状态

5A 完成条件：

- 每条跨书关系能追溯到关系两端的来源片段。
- 同一名称在未确认身份一致前不自动合并。
- 可以按症状或证候查看不同书的论述、穴位、经方和差异。
- 输出是有出处的传统医学知识比较，不是自动形成的个人治疗处方。

### 阶段 5B：接入 AI

AI 层只建立在正式证据库、完整检索层和 5A 知识网络之上。

建设内容：

- 继续使用当前 FastAPI 架构，增加独立 AI 服务层。
- 首版优先使用结构化索引和全文搜索；当资料量和语义检索需求证明有必要时，再评估向量 RAG。
- 为已验证知识建立全文和结构化检索索引。
- 检索结果包含来源页、原文片段和审核状态。
- 回答区分原文、讲解、整理说明和模型解释。
- 对证据不足、版本冲突和高风险内容返回不确定性。
- 不根据单个症状直接生成诊断或处方。
- 对针刺操作、剂量和毒性内容使用严格回答边界。
- 对涉及真实患者的信息，明确医疗安全、个人信息和专业人员审核边界。
- 建立固定评测集，覆盖引用正确性、版本冲突、拒答和风险提示。

完成条件：

- 回答中的关键结论可点击回到来源证据。
- 没有证据时明确说明不足。
- 不允许模型补充不存在的页码或原文。
- 高风险问题有稳定拒答或安全转介行为。

## 九、跨阶段工作流

每一批知识都按以下顺序处理：

1. 来源登记和哈希校验
2. 目录或章节分母建立
3. 页图与 OCR
4. 人工校字
5. 结构化抽取
6. 实体与关系生成
7. 来源完整性检查
8. 内容风险检查
9. 人工审核
10. 批次签收
11. 页面和 API 回归测试

批次只有在 manifest 中签收后，才能改变正式统计数字。候选批次可以进入预览区，不能进入正式学习路径。

## 十、运行存储决策

初期继续使用现有 JSON 和 Python ETL，不在针灸阶段重写数据层。以下条件同时或明显出现时，再评估引入 SQLite：

- 跨经络、穴位、本草、方剂和证候的多跳查询开始频繁
- 关系完整性无法继续依靠小型索引脚本可靠检查
- 批次审校需要事务保证
- 页面搜索需要跨多个大 JSON 文件反复全量加载

迁移时应保留 JSON 作为导入和审计格式，SQLite 作为查询和事务层，不能只保留不可审计的数据库副本。

## 十二、质量与验收体系

### 来源检查

- 每个正式记录至少有 1 个有效来源片段。
- 来源片段必须能在对应页图中找到。
- PDF 页码、印刷页码和章节路径必须一致。
- 引文哈希变化必须触发复核。
- 不允许引用不存在或未登记的页码。

### 结构检查

- 目录标题和实际内容页数可核对。
- 所有实体 ID 唯一。
- 所有关系两端存在。
- 别名不覆盖规范名。
- 同名方剂和同名穴位不能因规范化被错误合并。

### 回归检查

- 现有方剂和本草测试始终通过。
- 新模块批次有独立测试。
- 页面统计数字只能从 manifest 生成。
- 状态展示与数据状态一致。

### 内容检查

- 原文和解释分离。
- 版本冲突保留。
- 高风险内容有警示。
- 未经审核的内容不被 AI 正式引用。
- 不出现伪造出处、空泛引用和不可定位的“某书说”。

## 十三、主要风险与应对

| 风险 | 应对 |
|---|---|
| PDF 文本层乱码 | 页图优先，OCR 与校字稿双层保存 |
| PDF 页码与印刷页码错位 | 每个来源单独维护两套页码 |
| Book to Skill 摘要被误当原文 | Skill 与证据库物理分离，正式数据只读证据片段 |
| 原始 PDF 文本层乱码导致 Book to Skill 输入失真 | 先 OCR 和校字，再对清洁文本运行 Book to Skill |
| 项目内 Skill 目录未被 Codex 自动发现 | 阶段 0 做最小技能发现测试，必要时安装到 `~/.agents/skills/` |
| 自动抽取被误认为已审核 | 四个正交状态分离展示 |
| 版本差异被合并 | 版本、异文和冲突记录独立 |
| 现有方剂数据被重写 | 兼容读取、批次 manifest、回归测试 |
| 针灸高风险内容被误用 | 风险状态、专业内容标记和回答边界 |
| 本草条目数被误称完整 | 先建立来源分母，再报告覆盖率 |
| 黄帝内经只有讲义转录 | 经典原文和讲义分源，不混标版本 |
| 后续 AI 幻觉引用 | 检索必须返回证据，回答必须有引用校验 |

当前不提前给出日历工期。先使用手太阴肺经试点测出每页 OCR、校字、抽取和审核的实际吞吐，再据此估算针灸全章工作量。

## 十四、总体完成定义

只有当以下条件同时满足，V2 的知识底座才可以视为稳定：

- 针灸、神农本草经、黄帝内经和经方使用同一来源和审校口径。
- 所有正式知识都能回到页级证据。
- 未审核内容有明确隔离。
- 高风险内容有统一规则。
- 跨模块关系可追溯到两端来源。
- 原有方剂和本草能力没有回归。
- AI 只在正式知识路径上工作。
